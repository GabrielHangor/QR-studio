# QR Studio — краткий технический план

> **Версия:** 0.1 · **Дата:** 14 октября 2026 года  
> **Статус:** предварительная техническая архитектура для согласования  
> **Основание:** *QR Studio — Final Product Brief v1.3* и последующие договорённости о стеке, структуре монорепозитория и QR-движке.  
> **Цель:** подготовить основу для двух бесплатных релизов без преждевременной реализации биллинга и сложной инфраструктуры.

## 1. Выбранный стек

| Область | Решение | Назначение |
|---|---|---|
| Backend | **AdonisJS** | API, аккаунты, хранение динамических QR, перенаправления, аналитика |
| База данных | **PostgreSQL** | Пользователи, QR-маршруты, история изменений, агрегаты переходов |
| Frontend | **Vue SPA** | Личный кабинет, полный редактор, впоследствии админка |
| Landing | **Astro + Vue islands** | SEO-страницы, витрина продукта, публичный бесплатный редактор |
| QR Toolkit | **TypeScript + Vue UI** | QR-матрица, собственный рендеринг/экспорт, логика и компоненты редактора |
| Монорепозиторий | **pnpm + pnpm Workspaces** | Общие зависимости и локальные пакеты `workspace:*` |
| Инфраструктура | **Docker Compose** | Локальная БД и сервисы; простой деплой без Kubernetes |

**На старте не нужны:** Redis, Kafka, микросервисы, Turborepo/Nx, отдельная очередь и платёжная система. Новые компоненты добавляются по измеренной необходимости.

## 2. Структура монорепозитория

```text
qr-studio/
├── apps/
│   ├── landing/                   # Astro: лендинг и /qr-generator
│   ├── frontend/                  # Vue SPA: редактор, кабинет, админка
│   └── backend/                   # AdonisJS: API и redirects
├── packages/
│   ├── qr-toolkit/
│   │   └── src/
│   │       ├── engine/
│   │       │   ├── encoder/        # Данные → QR-матрица
│   │       │   ├── renderer/       # Матрица → SVG/визуальные элементы
│   │       │   ├── exporters/      # SVG/PNG
│   │       │   └── validation/     # Контраст, quiet zone, декодирование
│   │       ├── editor/             # Модель дизайна, пресеты, история, состояние
│   │       ├── ui/                 # Vue-компоненты и панели редактора
│   │       └── types/
│   └── shared/                    # Общие типы и контракты API
├── pnpm-workspace.yaml
├── package.json
├── pnpm-lock.yaml
└── docker-compose.yml
```

Один пакет **`@qr-studio/toolkit`** с независимыми точками входа: `/engine`, `/editor`, `/ui`. Импорт `/engine` не должен тянуть Vue. `landing` и `frontend` используют **один QR-редактор**, а не две реализации.

`pnpm-workspace.yaml`:

```yaml
packages:
  - 'apps/*'
  - 'packages/*'
```

Локальные зависимости подключаются через `workspace:*`; версию pnpm фиксируем через `packageManager` в корневом `package.json`.

## 3. Принцип работы QR Toolkit

```text
Контент (URL / текст)
    ↓
QR encoder (проверенная библиотека) → QR-матрица
    ↓
Собственный renderer → единая визуальная модель / SVG
    ↓
Preview и экспорт SVG / PNG
```

**Решение:** не писать QR-алгоритм с нуля. Выбрать надёжный **encoder, отдающий матрицу**, а визуальный renderer и интерфейс редактора создать самостоятельно. Конкретную библиотеку выбрать после маленького technical spike (сравнить API, лицензию, ограничения и корректность кодирования).

`engine` отвечает за результат, `editor` — за параметры дизайна и действия пользователя, `ui` — за Vue-представление. Визуальные параметры храним в сериализуемой модели, чтобы шаблоны можно было повторно применять и экспортировать. Предпросмотр и экспорт должны опираться на один рендеринг. Для статических QR вводимый текст и логотип по возможности **не покидают браузер**.

## 4. Публичный интерфейс

- **Главная (`/`):** описание продукта, демонстрация возможностей и **облегчённый интерактивный блок** с переходом в полный редактор. Это не отдельный генератор, а упрощённая конфигурация общих компонентов.
- **`/qr-generator`:** **полный бесплатный редактор статических QR без регистрации**, Vue island внутри Astro.
- **Vue SPA (`app.*` или отдельный путь):** тот же редактор, плюс личный кабинет, сохранённые динамические QR и Analytics Lite после Release 1.

Точное разбиение по доменам и стратегия авторизации/CORS — отдельное небольшое решение перед Release 1.

## 5. Границы двух релизов

### Release 0 — бесплатный редактор

1. Technical spike: библиотека кодирования → матрица → собственный SVG → PNG, тест декодирования.
2. Компоненты редактора: URL/текст, live preview, формы, цвета/градиенты, логотип, отступы, рамки, несколько качественных пресетов.
3. Scan-safe проверки и предупреждения; качественный SVG/PNG-экспорт.
4. Astro-лендинг, SEO-страница полного редактора, мобильная адаптация.
5. Минимальная продуктовая аналитика **без хранения содержимого статических QR**: открытие редактора, использование инструментов, экспорт.

**Не нужны:** регистрация, база данных для генерации, динамические ссылки, платные ограничения.

### Release 1 — динамические QR и Analytics Lite

1. Аккаунты, вход, кабинет и список QR.
2. Создание управляемой короткой ссылки и изменение её назначения.
3. `GET /r/:code` → проверка активного маршрута → **HTTP 302/307** с целевым URL; не использовать постоянный 301 для изменяемых целей.
4. Счётчик переходов за всё время + агрегаты по дням **за последние 7 дней** (рабочая гипотеза); без обязательного длительного хранения сырых событий.
5. Настраиваемый лимит числа активных бесплатных динамических QR (**3 — предварительная гипотеза**, не утверждённый тариф).
6. Мониторинг редиректов, резервное копирование маршрутов, ограничение злоупотреблений, безопасная валидация целевых URL и понятные условия беты.

При сбое аналитики **редирект должен продолжать работать**. Для MVP допустима потеря отдельных второстепенных событий статистики; надёжность маршрутов важнее полноты счётчика.

## 6. Минимальная серверная модель (Release 1)

- `users` — учётные записи.
- `dynamic_qrs` — владелец, короткий идентификатор, целевой URL, название, статус, даты.
- `qr_redirect_history` — изменение назначения для аудита действий владельца.
- `qr_daily_stats` — ID кода, день, количество переходов.
- `total_redirects` — общий накопительный счётчик (поле или отдельный агрегат).

Это **логические сущности**, а не утверждённые SQL-таблицы. Точную схему, конкурентное обновление счётчиков и срок хранения определить в PRD/дизайне Release 1.

## 7. Минимальное качество и безопасность

- **QR:** тесты корректного декодирования для разных размеров, уровней коррекции ошибок, логотипов и цветов; ограничения на рискованную стилизацию. Физическую печать проверять отдельно.
- **Backend:** проверка владельца при редактировании, лимит запросов, безопасные URL и блокировка очевидно вредоносных назначений, отсутствие открытого произвольного redirect endpoint.
- **Redirects:** быстрый путь без тяжёлой бизнес-логики; мониторинг доступности, HTTPS, проверенное восстановление резервной копии.
- **Данные:** минимизация учётных/аналитических данных, понятная политика хранения; требования РФ к персональным данным оценить перед публичным запуском аккаунтов.
- **Тесты:** unit для engine/editor, интеграционные для API/redirects, E2E для сценария «настроить → скачать» и затем «создать динамический → изменить URL → перейти».

## 8. Что оставляем открытым

1. Какую библиотеку использовать только для **QR encoding**.
2. Детали renderer: SVG-first, необходимость Canvas для preview/PNG и компромиссы производительности.
3. UI-архитектура редактора, набор настроек и модель шаблонов — отдельный **PRD QR Editor**.
4. Размещение SPA/API по доменам, подход к сессиям и CORS.
5. Реализация неблокирующего подсчёта переходов **без сложной очереди**.

**Вне текущего плана:** платежи, тарифы, grace period, QR Ownership/custom domains, геоаналитика, Brand Kit, команды и массовая генерация.

## 9. Ближайшая последовательность

**Сначала:** создать pnpm-монорепозиторий и провести технический spike encoder + собственный renderer + SVG/PNG + проверка читаемости. **Затем:** согласовать PRD редактора и реализовать Release 0. Только после его публикации детализировать серверный Release 1.

> **Критерий успеха Release 0:** посетитель без регистрации может быстро создать визуально качественный, проверяемо считываемый QR-код и скачать его.  
> **Критерий успеха Release 1:** зарегистрированный пользователь может создать динамический QR, поменять назначение и увидеть базовую статистику без сбоев редиректов.
