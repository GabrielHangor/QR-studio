# QR Studio — технический план

Основа: v0.1 от 14.10.2026. Актуальная редакция: 17.10.2026.
Границы продукта — в [брифе](./qr-studio-final-product-brief-ru-v1.4.md), требования редактора — в [PRD](./qr-editor-prd-release-0-ru-v0.1.md).

## Принятые решения

| Область | Решение | Состояние |
|---|---|---|
| Монорепозиторий | pnpm Workspaces, `apps/*` и `packages/*` | Настроен |
| QR Encoder | `qr@0.7.2` от Paul Miller, адаптер к собственному `QrMatrix` | Реализован |
| Renderer | Собственный синхронный SVG Renderer без DOM/Vue | Реализован |
| PNG | Растеризация того же SVG в браузерном слое | Playground и Vue editor |
| Toolkit tooling | TypeScript, Vite, Vitest, Oxlint, Oxfmt | Настроено; Vite+ не используется |
| Публичные страницы | Astro + Vue island, `/qr-generator` | План |
| Кабинет | Vue SPA на Vite + Nuxt UI, тема Iris | Editor URL/Text со всеми настройками playground |
| Backend | AdonisJS + PostgreSQL | План для Release 1 |
| Инфраструктура | Docker Compose для локальных сервисов | Только пустая заготовка |

Корень не содержит зависимостей: только общие скрипты, workspace/lockfile и версии Node/pnpm.
Каждое приложение владеет своими TypeScript, линтером, форматтером и зависимостями;
AdonisJS не обязан разделять инструменты toolkit. Локальные пакеты подключаются через `workspace:*`.
В frontend/toolkit/theme есть локальные `.oxlintrc.json`: correctness, suspicious,
TypeScript, Vue для UI-пакетов и Vitest для тестов toolkit. Окружения браузера/Node
разделены через overrides; сборки, отчёты и зависимости исключены.
`pnpm lint` отклоняет предупреждения, `pnpm lint:fix` применяет обычные безопасные
автоисправления. Форматированием занимается Oxfmt, проверкой типов и Vue-шаблонов — vue-tsc.
Правила читаемости: скобки в многострочных ветках (короткие guard clauses разрешены),
без лишних `else`/`return` и повторных импортов, shorthand свойств и явные type imports.
Разрешены `value == null`, локальные функции, оба стиля type imports и явные типы
параметров/свойств. Лимиты длины, сложности, именование и принудительный выбор
`interface`/`type` не вводятся; категории style/pedantic целиком не включаются.
Redis, очереди, микросервисы и Turborepo/Nx добавляются только по измеренной необходимости.

## Границы пакетов

```text
apps/landing        Astro: лендинг и публичный редактор          [план]
apps/frontend       Vue SPA: подключён общий Vue editor
apps/backend        AdonisJS: API, маршруты, аналитика             [план]
packages/qr-toolkit  headless engine + i18n + /ui + playground
packages/theme       переносимые CSS-токены Iris + адаптер Nuxt UI
packages/shared     общие API-типы/схемы                          [резерв]
```

Существующие entrypoint `@qr-studio/toolkit`: `/engine`, `/i18n`, `/i18n/ru`, `/i18n/en`.
`/ui` экспортирует Vue editor и composable: URL/Text, live preview, оформление,
SVG/PNG-экспорт, диагностика и локализация. `/editor` содержит типы состояния, фабрику и подготовку payload
без Vue/DOM, включая применение внешних пресетов и черновики подписей.
Корневого entrypoint нет. Engine/i18n собираются в ESM и `.d.ts`; runtime-зависимость engine — `qr`.
Vue и Nuxt UI — optional peers: обязательны только для UI-потребителя.

Frontend владеет Nuxt UI plugin, `UApp` и единственным импортом глобального CSS.
Iris (Violet/Fuchsia/Mauve, Manrope, Remix Icons) задаётся пакетом `theme`; plain CSS-токены
доступны будущему лендингу без Vue. Vite компилирует `/ui` прямо из исходников с HMR,
`resolve.dedupe` объединяет Vue/Nuxt UI; `scanPackages` и Tailwind `@source` охватывают пакет.
TypeScript 6.0.3 закреплён в frontend/toolkit из-за несовместимости vue-tsc 3.3.13 с TypeScript 7.
Подробный API и команды — в [README пакета](../packages/qr-toolkit/README.md).

## Pipeline QR

```text
Форма содержимого → payload builder → строка
  → encodeQr → QrMatrix → renderQrSvg → SVG для preview/скачивания
                                      → растеризация PNG в браузере
```

- `encodeQr` передаёт строку без нормализации; ECC по умолчанию M, версия автоматически или 1–40.
- `QrMatrix` содержит модули без полей, версию, размер, ECC, маску служебных зон и координаты маркеров. Маску toolkit строит по версии символа; адаптер удаляет техническую рамку encoder.
- Renderer принимает матрицу и параметры оформления, не знает о формах данных, пресетах, состоянии контролов или языке.
- `analyzeQrDesign` возвращает измерения и `code + severity + params`. Пороги контраста и размера модуля задаёт потребитель после испытаний, универсальные безопасные числа не утверждены.
- Ошибки `QrError` / `QrEncodingError` содержат `code + params`; отдельный типизированный маппер использует переданный словарь RU/EN или словарь приложения. Исходная причина нужна для отладки, не для вывода пользователю.
- Каталог пресетов принадлежит приложению. Engine получает обычный `RenderQrSvgOptions`, не ID пресета.
- Браузерный UI отвечает за контролы, загрузку ассетов, preview и экспорт PNG. Vue editor — отдельный потребитель engine. Загрузка логотипа и экспорт защищены от устаревших асинхронных результатов при смене данных.

URL/Text уже проходят строковую границу. Wi-Fi/vCard — отдельные P1-сериализаторы,
которые не меняют encoder/renderer. Формат версионируемого дизайн-проекта нужен перед сохранением P1.

## Release 1: серверная часть

Логические сущности: пользователь; динамический QR (владелец, короткий код, цель, название,
статус, даты); история смены назначения; общий счётчик и дневные агрегаты.
Это не утверждённая SQL-схема.

`GET /r/:code` → поиск активного маршрута → временный 302/307 на проверенный HTTP(S) URL.
Произвольный открытый redirect endpoint не нужен; постоянный 301 не подходит для сменяемой цели.
Сбой аналитики не должен срывать редирект: допустима потеря второстепенного события.
Конкретный механизм обновления агрегатов без сложной очереди ещё нужно выбрать.

До запуска: проверка владельца, безопасные URL, rate limits/abuse-жалобы, HTTPS,
мониторинг, копии маршрутов с восстановлением и понятные условия беты.
Доменное разбиение SPA/API/redirect, сессии/CORS, схема БД и сроки хранения пока открыты.

Проверки по мере появления модулей: unit для engine/editor, интеграционные для API/redirects,
E2E «настроить → скачать», затем «создать динамический QR → сменить URL → перейти».

## Что проверить дальше

1. Функциональные `test:scan` уже декодируют реальный SVG/PNG в Chromium через независимый ZXing WASM. Расширять фиксированную матрицу по найденным случаям; телефоны и физическая печать остаются отдельной проверкой.
2. Матрица испытаний форм, градиентов, логотипа, контраста, плотности и размеров. ECC не равен безопасной площади логотипа.
3. Производительность стилизованного SVG на целевых мобильных устройствах и допустимые размеры экспорта.
4. Удобство полного Vue editor на desktop/mobile; версионируемый проект и хранение — только перед P1.
5. Завершение Release 0, затем отдельная спецификация серверного Release 1.

Полный сравнительный UX-тест конкурентов остаётся исследовательской задачей, а не выполненной
проверкой engine и не обязательным поводом повторять уже завершённый выбор encoder.
Текущий прогресс и результаты ручных прогонов — в [README документации](./README.md).
