# Работа с QR Studio

Перед изменениями прочитай [README](README.md), затем профильный документ:
[продукт](docs/product.md), [архитектуру](docs/architecture.md) или
[API toolkit](packages/qr-toolkit/README.md). Не требуется перечитывать весь набор для каждой задачи.
Более поздние явно согласованные решения пользователя имеют приоритет.
Существенные противоречия обозначай, не решай за владельца проекта.

- Предпочитай небольшие проверяемые изменения; выполняй релевантные проверки из README.
- Не добавляй зависимости, сервисы и функции без необходимости. Инструменты принадлежат использующим их пакетам.
- Сохраняй границы engine/editor/UI, описанные в архитектуре.
- Не коммить секреты и реальные пользовательские данные.
- Конкурентные утверждения проверяй по датированным источникам; факт и гипотеза различаются.
- Каждое решение описывай в одном профильном документе, в остальных ставь ссылки.
- Допустимые значения и полный перечень полей хранятся в типах и конфигурациях кода.
  В документации оставляй примеры, назначение API и неочевидные ограничения.
- История изменений хранится в Git. Исследования в `docs/archive` не задают текущие требования.
