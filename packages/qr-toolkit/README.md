# @qr-studio/toolkit

Первая версия общего headless QR-движка QR Studio. Пакет использует TypeScript
для сборки, Vite для playground, Vitest для тестов, а также Oxlint и Oxfmt.

## Использование

```ts
import { encodeQr, renderQrSvg } from "@qr-studio/toolkit/engine";

const matrix = encodeQr("https://example.com", { errorCorrectionLevel: "M" });
const svg = renderQrSvg(matrix, {
  size: 512,
  foreground: "#123456",
  background: "#ffffff",
});
```

`encodeQr` использует `qr` от Paul Miller и возвращает собственный контракт
`QrMatrix`: версию, размер, ECC и строки модулей `modules[row][column]` без полей.
`qr` 0.7.2 требует положительный border даже для raw; адаптер запрашивает один
модуль поля и удаляет его, не изменяя содержимое символа.
URL и текст передаются без нормализации. Версия выбирается автоматически, если
не задано значение 1–40. ECC по умолчанию — M. Пустой текст и переполнение
ёмкости приводят к исключению.

`renderQrSvg` синхронно возвращает самодостаточный SVG без обращения к DOM,
серверу или encoder. Одну матрицу можно рендерить повторно с другим оформлением.
Соседние тёмные модули объединяются в горизонтальные участки одного path.
Quiet zone по умолчанию равна 4 модулям; уменьшить её ниже 4 нельзя.
Цвета принимаются только в непрозрачном формате #RGB/#RRGGBB.
SVG-строка служит общим результатом для будущих preview и экспорта.

Движок не импортирует Vue. Корневого entrypoint пока нет: потребители используют
`/engine`; `/editor` и `/ui` появятся вместе с соответствующей реализацией.
Сборка — ESM и декларации `.d.ts`; `qr` остаётся runtime-зависимостью.

## Команды из корня репозитория

```sh
pnpm install
pnpm --filter @qr-studio/toolkit build
pnpm --filter @qr-studio/toolkit check
pnpm --filter @qr-studio/toolkit test
pnpm --filter @qr-studio/toolkit playground
```

`playground` запускает локальную страницу: ввод URL/текста, живой SVG-предпросмотр
и скачивание того же SVG. При пустом вводе или ошибке экспорт недоступен.
Страница состоит из HTML/CSS/TypeScript и использует обычный Vite.
`dev` пересобирает библиотеку при изменениях.
`build:playground` собирает страницу в `dist-playground`, отдельно от библиотеки.

Версия Node закреплена в корневом `.nvmrc`: перед работой выполните `nvm use`.
Версия pnpm должна совпадать с корневым `packageManager` (`12.11.2`).

## VS Code

Откройте в VS Code обычную корневую папку `QR Studio`. Настройки `.vscode/settings.json`
направляют расширение Oxc к локальным `oxlint` и `oxfmt` из toolkit. После первой
установки зависимостей, если редактор не обнаружил бинарники, выполните команды
**Oxc: Restart oxlint Server** и **Oxc: Restart oxfmt Server**.

`build` компилирует библиотеку через `tsc`, `test` запускает Vitest, `lint` — Oxlint,
`format` — Oxfmt. Команда `check` объединяет lint, проверку типов и форматирования.

## Проверки и границы версии

Тесты проверяют контракт матрицы, расположение модулей в SVG, quiet zone,
повторный рендер, ECC и входные ограничения.
Автоматическое декодирование и растеризация SVG сейчас не проверяются;
независимый decoder выберем отдельно перед усложнением стилизации.

Это базовый технический срез, а не завершённый Scan-safe или редактор:

- Пока поддерживаются квадратные модули и два сплошных цвета.
- Нет классификации служебных областей, декоративных форм, градиентов и логотипа.
- Нет PNG exporter, Vue UI, сохранения проектов и сетевых запросов.
- Контраст и физический размер не проверяются; заданные цвета могут ухудшить чтение.
- Считывание на телефонах и после печати требует отдельной проверки.
- Производительность в браузере и на мобильных устройствах ещё не измерена.
- Encoder `qr` использует один сегмент; смешанные payload могут давать более
  плотную матрицу, чем при оптимизированной сегментации.
