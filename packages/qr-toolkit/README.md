# @qr-studio/toolkit

Headless QR Engine: `qr@0.7.2` от Paul Miller → собственная матрица → собственный SVG Renderer.
Без Vue/DOM и каталога пресетов внутри engine. Единственная runtime-зависимость — `qr`.
Engine и `/editor` собираются в ESM и `.d.ts`; Vue editor доступен через `/ui`. Корневого entrypoint нет.
Контекст продукта и статус проекта — в [документации](../../docs/README.md).

## Запуск из корня

```sh
nvm use
pnpm install
pnpm dev
```

Node закреплён в `.nvmrc`, pnpm — в корневом `packageManager`.
Редактор для ручной проверки работает в `apps/frontend`; над ним есть переключатель
полной и компактной конфигураций. Отдельного playground в toolkit нет.
Инструменты локальны пакету: TypeScript, Vite, Vitest, Oxlint и Oxfmt. Vite+ не используется.

| Команда после `pnpm --filter @qr-studio/toolkit` | Результат                                              |
| ------------------------------------------------ | ------------------------------------------------------ |
| `build` / `dev`                                  | ESM + декларации в `dist` / пересборка при изменении   |
| `check`                                          | Линтер, типы библиотеки/UI/scan-тестов, форматирование |
| `test`                                           | Быстрые Node-тесты Vitest                              |
| `format`                                         | Oxfmt                                                  |
| `test:scan`                                      | Декодирование SVG/PNG в Chromium через ZXing WASM      |

## API engine

```ts
import {
  encodeQr,
  renderQrSvg,
  analyzeQrDesign,
  type RenderQrSvgOptions,
} from "@qr-studio/toolkit/engine";

const matrix = encodeQr("https://example.com", { errorCorrectionLevel: "M" });
const design: RenderQrSvgOptions = {
  size: 512,
  foreground: "#173d51",
  moduleShape: "rounded",
  finder: { outerShape: "rounded", innerShape: "circle" },
};
const svg = renderQrSvg(matrix, design);
const analysis = analyzeQrDesign(matrix, design);
```

`encodeQr` принимает строку без нормализации; ECC по умолчанию M, версия автоматически
или вручную 1–40. `QrMatrix` содержит `modules[row][column]` без полей, размер, версию,
ECC, `functionModules` и координаты трёх finder patterns. Маска служебных зон строится
в toolkit. Техническая рамка encoder в один модуль удаляется адаптером.

`renderQrSvg` синхронно возвращает детерминированную SVG-строку. Повторное оформление
матрицы не требует кодирования. Полный тип опций — [types.ts](./src/engine/types.ts).

| Опция                        | Контракт                                                                                                                                                                                     |
| ---------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `size`, `quietZone`          | Ширина композиции в px (512 по умолчанию); поле в модулях (минимум и default 4)                                                                                                              |
| `foreground`, `background`   | Непрозрачные `#RGB`/`#RRGGBB`; foreground также принимает `{ type: "linear", direction, startColor, endColor }`, direction: horizontal/vertical/diagonal                                     |
| `moduleShape`                | square/rounded/circle/soft/leaf/leaf-reverse; timing/alignment и прочие служебные зоны остаются квадратными, кроме отдельно оформленных finder patterns                                      |
| `finder`                     | Цельные кольцо/центр: outerShape/innerShape и независимые outerColor/innerColor. Без своих цветов наследуют foreground                                                                       |
| `finderShape`                | Прежняя стилизация клеток маркеров; `finder` имеет приоритет                                                                                                                                 |
| `shape`, `artworkBackground` | Внешняя square/circle форма и её фон; полная квадратная QR-подложка с quiet zone сохраняет `background`                                                                                      |
| `frame`                      | none/outline; `{ style: "dashed" }` или `{ style?, color?, widthPx? }`; у объекта default 2 px, толщина меньше четверти ширины. Прежний строковый outline сохраняет толщину в модулях        |
| `logo`                       | Центрированный base64 PNG/JPEG/WebP: dataUri, widthModules, paddingModules, clearBackground. SVG-ассет и перекрытие служебных зон запрещены                                                  |
| `caption`                    | Одна подпись или две, по одной top/bottom. style: plain/banner/arc; дуга только у circle. Цвет, фон полосы, fontSize (max px, default 18), fontWeight 400/500/600/700, letterSpacing 0–10 px |

Градиент един для всей матрицы и наследующих его маркеров (`userSpaceOnUse`). Круг
вмещает квадрат вместе с quiet zone, оставляет прозрачные углы и при той же ширине
уменьшает QR. Прямые подписи увеличивают высоту; дуги занимают свободные верх/низ,
не уменьшая код. Текст и межбуквенный интервал автоматически уменьшаются до доступного места.
Рамка и подписи находятся за quiet zone.

`analyzeQrDesign` возвращает `contrastRatio` (null для градиента), `modulePitchPx`,
`logoCoveragePercent` и `diagnostics`. Третий аргумент принимает проверенные потребителем
пороги `minimumContrastRatio` и `minimumModulePitchPx`; безопасные универсальные значения
не установлены. ECC не задаёт разрешённую площадь логотипа, диагностика не гарантирует сканирование.

## Ошибки и языки

```ts
import { formatQrError, formatQrDiagnostic } from "@qr-studio/toolkit/i18n";
import { qrMessagesEn } from "@qr-studio/toolkit/i18n/en";
import { qrMessagesRu } from "@qr-studio/toolkit/i18n/ru";

try {
  encodeQr("https://example.com", { version: 0 });
} catch (error) {
  const text = formatQrError(error, qrMessagesRu);
  // Версия QR должна быть целым числом от 1 до 40.
}
const warnings = analysis.diagnostics.map((item) => formatQrDiagnostic(item, qrMessagesEn));
```

`QrError` содержит `code + params`; `QrEncodingError` наследует контракт и сохраняет
`cause`/`originalError` для отладки. Диагностика: `code + severity + params`.
`Error.message` — технический код, не пользовательский текст; у диагностик `message` нет.
Валидация renderer/analyzer бросает `QrError`, а не `TypeError`/`RangeError`.
Конструктор: `new QrEncodingError(code, params, originalError?)`.

Приложение выбирает словарь RU/EN либо реализует `QrMessageCatalog`: обработчик параметров
каждого кода в `errors`/`diagnostics` и `unknownError`. TypeScript проверяет полноту;
числа форматирует словарь. Engine не импортирует переводы и не хранит текущий язык.
Для неизвестного исключения `formatQrError` возвращает `unknownError` или третий аргумент;
произвольные технические сообщения и исходная причина не показываются пользователю.

## Внешние пресеты

Engine принимает обычный `RenderQrSvgOptions`, не ID: дизайн может приходить из конфигурации,
API или внешнего каталога. Каталог интерфейса находится в `apps/frontend/src/presets.ts`
и передаётся в `QrEditor` через `presets`. Выбор пресета сохраняет payload, ECC,
версию, размер, quiet zone и загруженный логотип.

Шесть фиксированных дизайнов для тестов геометрии и считывания находятся в
`tests/fixtures/design-presets.ts`. Они не зависят от интерфейса и не входят в сборку библиотеки.

## Функциональные тесты экспорта

Быстрые `test` проверяют матрицы/служебные зоны версий 1–40, геометрию, ограничения,
диагностику и RU/EN. Отдельный `test:scan` запускает [Vitest Browser Mode](https://vitest.dev/guide/browser/)
с Chromium: настоящий SVG → браузерная растеризация → PNG → независимый [ZXing WASM](https://github.com/Sec-ant/zxing-wasm).
Это функциональные интеграционные тесты pipeline экспорта, без моков; клики по UI они не проверяют.

Из корня, для первого запуска или после смены версии Playwright:

```sh
nvm use
pnpm install --frozen-lockfile
pnpm --filter @qr-studio/toolkit test:scan:install
pnpm --filter @qr-studio/toolkit test:scan
```

На Linux CI системные зависимости браузера ставятся через
`pnpm --filter @qr-studio/toolkit exec playwright install --with-deps chromium`.
Для полной проверки запускайте `check`, `test` и `test:scan`; обычный `test` браузер не запускает.
Один сценарий: `pnpm --filter @qr-studio/toolkit test:scan -t atelier-url-256`.

Набор в `tests/scan/cases.ts` фиксирован: все шесть тестовых пресетов × четыре payload × два размера;
уменьшение до 60%, blur 0.6 px и JPEG quality 0.72 для пресетов при 512 px; версии
1/7/10/27/40 × ECC L/M/Q/H; комбинации форм маркеров; длинный Unicode; растровый логотип.
Дополнительно проверяются 16 пресетов frontend на 256/512 px и новые формы точек/маркеров.
Отдельный отрицательный контроль проверяет отсутствие QR на пустом изображении.
Проверяются точный payload, ширина SVG и прозрачные углы круглой композиции.
Эти размеры и искажения — условия теста, не универсальные безопасные пределы.

Для воспроизводимости зависимости и Chromium закреплены lockfile/Playwright;
WASM локальный, без CDN; locale, timezone, viewport и device scale заданы явно.
QR декодируется целиком на белой подложке, без обрезки декора или подмены матрицей.
ОС/системные шрифты могут менять растеризацию подписей: это не пиксельные snapshot-тесты;
для сравнения байтов нужен одинаковый образ ОС. Измерения времени справочные, без нестабильных порогов.

В `packages/qr-toolkit/test-results/scan/` создаются `vitest.json`, `summary.json`
(результаты, декодированные строки, размеры, диагностика, время/объём SVG) и `environment.json`
(Node/ОС/архитектура/версии пакетов). При сбое в `failures/` сохраняются параметры,
исходный SVG, экспортированный PNG и изображение после искажения, если они были созданы.
Каталог исключён из Git и очищается перед каждым прогоном; в CI сохраняйте его как artifact даже при ошибке.

## Ограничения

Прохождение тестов подтверждает только выбранные сочетания и синтетические искажения,
не универсальное считывание или физическую печать. Телефоны, пороги читаемости и мобильная
производительность пока требуют проверки; текущий статус — в [документации](../../docs/README.md).
Обычные квадратные модули объединяются в path; сложная стилизация создаёт больше элементов.
Encoder использует один сегмент: смешанное содержимое может кодироваться менее плотно,
чем при оптимизированной сегментации. Сохранение проектов ещё не реализовано.

## Vue editor

`@qr-studio/toolkit/ui` экспортирует `QrEditor`, `useQrEditor`, фабрику
`createQrEditorState` и словари `qrEditorMessagesRu` / `qrEditorMessagesEn`.

```vue
<script setup lang="ts">
import { ref } from "vue";
import { QrEditor, createQrEditorState, fullEditorConfig } from "@qr-studio/toolkit/ui";
const state = ref(createQrEditorState());
</script>

<template>
  <QrEditor v-model="state" :config="fullEditorConfig" locale="ru" />
</template>
```

Внутренние панели находятся в `src/ui/components`: `QrContentForm` отвечает за поля
и blur-состояние, `QrShapeControls` — за формы, `QrPreview` — за SVG,
пустое состояние, ошибки и диагностику. `QrEditor` владеет общим состоянием,
выбором словаря и компоновкой; панели сообщают об изменениях через типизированные
события и не создают копий состояния. Эти панели не входят в публичные exports.

`v-model` необязателен; без него состояние локально компоненту. URL и текст хранятся
отдельными черновиками. URL требует HTTP(S) и полного адреса; обрезаются только крайние
пробелы. Текст кодируется дословно, включая пробелы и переносы. Изменение оформления
переиспользует матрицу. Неверный ввод, переполнение и ошибки renderer убирают старый preview.
Preview — SVG renderer в изолированном `img` с data URI: без вставки пользовательского HTML
и без lifecycle object URL.

`createQrEditorState()` возвращает независимое состояние с примером `https://example.com`,
текстом `QR Studio`, ECC M и базовым оформлением. QR виден сразу; пустой или неверный ввод
по-прежнему скрывает preview и блокирует скачивание. Переданное через `v-model` состояние
не заменяется примером. На desktop используются две колонки; пресеты и формы выбираются
визуальными radio-карточками с поддержкой клавиатуры. Рекомендации рядом с preview
свёрнуты в отдельный аккордеон. Успешное считывание выделяется зелёным бейджем;
изменение QR сбрасывает результат проверки.
Типы URL, текст, email, телефон, SMS, Wi-Fi, контакт vCard и координаты переключаются сверху.
Все типы получают независимые демонстрационные данные и сразу показывают QR.
Валидация содержимого и ошибки отдельных полей используют общие схемы Valibot. Все настройки, включая пресеты и технические параметры,
входят в один аккордеон: одновременно открыт только один блок. Селектор примеров удалён.
Для цветов есть компактные палитры по восемь оттенков с фиксированным размером образцов.
Названия пресетов скрыты визуально и остаются
доступными скринридеру. Формы точек/маркеров: square, rounded, circle, soft, leaf, leaf-reverse.
Рамка поддерживает сплошную обводку и `{ style: "dashed" }`.

Доступны формы модулей и маркеров, цвета и градиенты, квадратная/круглая композиция,
внешний фон, рамка, две подписи (прямые, полосы, дуги), растровый логотип, ECC и quiet zone.
Дополнительные цвета и точные параметры логотипа свёрнуты; размер логотипа регулируется
ползунком. Оформление надписи появляется после ввода текста, толщина шрифта и интервал
между буквами находятся в «Дополнительно». Сворачивание не сбрасывает значения.
Разрешение PNG выбирается ползунком рядом со скачиванием: 256/512/1024/2048 px,
с фактическими размерами изображения и пояснением о векторном SVG. Масштаб preview
от разрешения не зависит. Desktop preview ограничен высотой viewport; в низких окнах
его содержимое прокручивается, сохраняя минимальный размер QR. Версия QR подбирается автоматически;
ручная версия и измерения доступны через API engine, без контролов в редакторе.
Исходный SVG можно получить через `renderQrSvg` или скачать из редактора.
Предупреждения о формах и градиенте объединены в одно напоминание о проверке камерой;
конкретные риски показываются отдельно. Есть проверка через `BarcodeDetector`, если API
доступен. При ошибке экспорт блокируется.

`presets` принимает внешний `readonly QrDesignPreset[]` и необязателен.
Пресет меняет оформление, сохраняя содержимое, encoding, размер, quiet zone и логотип.
Типы экспортируются через `/ui` и `/editor`; готового каталога в пакете нет.
Пустые черновики подписей сохраняют настройки, но не передаются renderer.
Логотипы PNG/JPEG/WebP до 700 КиБ читаются локально; SVG не принимается.
`logo.clearBackground` по умолчанию true: renderer не рисует целые ячейки под логотипом
и его отступом. Границы округляются наружу до сетки, без обрезанных фрагментов;
диагностика учитывает фактическую площадь. Точки не перемещаются, исходная матрица не меняется.
При false QR виден под прозрачными областями, paddingModules не применяется.
В обоих режимах перекрытие служебных зон запрещено.
PNG сохраняет прозрачность SVG; растеризация ограничена 16 777 216 пикселями.
Сохранение проектов ещё не подключено.
`messages` принимает полный `QrEditorMessages` для своего языка, включая словарь engine.
`locale="en"` выбирает встроенный английский; локаль внутренних Nuxt UI-компонентов
задаёт host через `UApp`.

`/editor` — отдельный ESM + `.d.ts` entrypoint с типами состояния, фабрикой и подготовкой
содержимого, без Vue/DOM. `/ui` — source-first entrypoint: host компилирует `src` через Vite.
Vue/Nuxt UI остаются optional peers для headless-потребителей; UI-host устанавливает их явно.
Host владеет Nuxt UI plugin, одним `UApp` и глобальным CSS; пример — `apps/frontend`.

Для IDE используется `src/ui/tsconfig.json` и локальный контекст `#build/ui/*`.
`prepare:ui` генерирует его в `node_modules/.nuxt-ui`; команда включена в `typecheck`
и запуск frontend. `/engine` продолжает собираться отдельно.

Проверки из корня: `pnpm test` — unit, `pnpm test:ui` — реальные действия в Chromium
(1280 и 390 px, включая скачивание и независимое декодирование PNG), `pnpm test:scan` — независимое декодирование SVG/PNG engine.
Для UI-тестов используется установленный Playwright Chromium; команда установки —
`pnpm --filter @qr-studio/toolkit test:scan:install`.

Для координат используется OpenLayers с растровыми тайлами OpenStreetMap, без API-ключа.
Компонент карты и его зависимости загружаются только при выборе типа «Координаты».
Клик по карте и перетаскивание маркера меняют оба поля атомарно; ручной ввод обновляет
маркер и центр карты. Доступны масштабирование, перемещение стрелками клавиатуры
и выбор центра карты. Колесо мыши продолжает прокручивать страницу.
Атрибуция OpenStreetMap всегда видна; тайлы кэширует браузер по HTTP-заголовкам,
предзагрузка областей отключена. Общедоступный сервер тайлов работает без SLA и
должен использоваться согласно https://operations.osmfoundation.org/policies/tiles/.
При недоступных тайлах ручной ввод координат и создание QR продолжают работать.
UI-тесты проверяют реальный OpenLayers; только изображения тайлов подменяются
локальным тестовым PNG, чтобы не зависеть от сети и не нагружать сервер OSM.

Поиск места в карте использует Photon (`https://photon.komoot.io/api/`) без ключа.
Запрос отправляется только по Enter или кнопке «Найти»; автозапросов при вводе нет.
Результаты проверяются Valibot, запросы разделены минимум секундой, до 64 запросов
кэшируются на 10 минут в пределах страницы. При смене запроса и закрытии компонента
запрос отменяется; устаревший ответ не меняет результаты. Публичный сервер Photon
допускает умеренное использование, без гарантий доступности; условия:
https://github.com/komoot/photon#demo-server. Для другого сервера/провайдера host может
передать `locationSearch: QrLocationSearch` в `QrEditor` без изменений компонентов.

Результаты проверки считывания показываются во всплывающей панели и не меняют
размер QR, положение кнопок или высоту preview. В OpenLayers закреплён локальный
патч `patches/ol@10.11.0.patch`: opt-in `wheelListenerPassive: true` используется
только вместе с `mouseWheelZoom: false`. Он сохраняет стандартное поведение библиотеки
для остальных карт. При обновлении OpenLayers патч нужно перепроверить.

### Конфигурация редактора

`QrEditor` требует явный `config: QrEditorConfig`. Готовые `fullEditorConfig` и
`compactEditorConfig` экспортируются через `/ui` и `/editor`; редактор не выбирает
конфигурацию по тарифу, маршруту или окружению. В `apps/frontend` родитель передаёт
полную или компактную конфигурацию через переключатель. При миграции существующих вызовов
нужно добавить `:config="fullEditorConfig"`.

```vue
<script setup lang="ts">
import { ref } from "vue";
import {
  QrEditor,
  createQrEditorState,
  compactEditorConfig,
  type QrEditorConfig,
} from "@qr-studio/toolkit/ui";

const state = ref(createQrEditorState());
const config = {
  ...compactEditorConfig,
  contentTypes: ["url"],
  sections: [
    { id: "content", controls: ["sampleHint"] },
    { id: "shapes", controls: ["moduleShape"] },
  ],
  choices: { ...compactEditorConfig.choices, moduleShape: ["square", "circle"] },
  export: {
    formats: ["png"],
    resolutions: [512, 1024],
    resolution: true,
    scan: false,
  },
} as const satisfies QrEditorConfig;
</script>

<template>
  <QrEditor v-model="state" :config="config" />
</template>
```

Конфигурация содержит:

- `contentTypes` — непустой список доступных типов, в порядке вкладок.
- `sections` — секции в порядке отображения. `controls` выбирает видимые контролы
  внутри специализированной секции; порядок контролов внутри неё остаётся фиксированным.
- `choices` — непустые списки форм точек, внешнего и внутреннего маркеров, композиции,
  рамок, заливки, ECC, стилей подписи и толщины шрифта.
- `ranges` — числовые `min/max/step` для quiet zone, рамки, размера/отступа логотипа,
  размера/интервала текста, плюс `captionTextMaxLength`.
- `palettes` — цвета образцов переднего плана и фона; пустая палитра оставляет ручной выбор.
- `export` — форматы, непустой список разрешений, видимость выбора разрешения и сканирования.
- `recommendations` — видимость рекомендаций в preview.

Полный тип и идентификаторы контролов находятся в `src/editor/config.ts`.
Секция пресетов отображается только при переданном каталоге; остальные секции с пустым
`controls` скрываются, кроме `content` с обязательными полями выбранного формата.
`locationSearch` в controls секции content действует вместе с `locationMap`.
Условное отображение внутри контролов сохраняется: например, отступ логотипа доступен
при очистке фона, фон подписи — при стиле banner, а arc требует круглой композиции.

`config` может быть реактивным или вычисляемым. Скрытые значения, черновики и параметры
экспорта сохраняются; смена вариантов выбора, палитры или диапазона не переписывает
текущее значение. Изменения происходят по действиям пользователя. Если текущий тип QR
исчезает из `contentTypes`, выбирается первый разрешённый, а все черновики сохраняются.
Текущая секция сохраняется, пока доступна; при её удалении открывается `initialSection`
или первая доступная. Закрытый пользователем аккордеон остаётся закрытым при обновлении
конфигурации. Начальные и фиксированные значения задаются отдельно в `v-model`.
Диапазоны и видимость ограничивают UI, а проверки корректности engine выполняются всегда.
Внешние сервисы (`locationSearch`) и каталог пресетов остаются отдельными props.
