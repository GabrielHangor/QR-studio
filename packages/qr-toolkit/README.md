# @qr-studio/toolkit

Первая версия общего headless QR-движка QR Studio. Пакет использует TypeScript
для сборки, Vite для playground, Vitest для тестов, а также Oxlint и Oxfmt.

## Использование

```ts
import { analyzeQrDesign, encodeQr, renderQrSvg } from "@qr-studio/toolkit/engine";

const matrix = encodeQr("https://example.com", { errorCorrectionLevel: "M" });
const svg = renderQrSvg(matrix, {
  size: 512,
  foreground: "#123456",
  background: "#ffffff",
  moduleShape: "rounded",
});
const diagnostics = analyzeQrDesign(matrix, { foreground: "#123456" });
```

`encodeQr` использует `qr` от Paul Miller и возвращает собственный контракт
`QrMatrix`: версию, размер, ECC, строки модулей `modules[row][column]` без полей,
маску служебных модулей и координаты трёх finder patterns.
`qr` 0.7.2 требует положительный border даже для raw; адаптер запрашивает один
модуль поля и удаляет его, не изменяя содержимое символа.
URL и текст передаются без нормализации. Версия выбирается автоматически, если
не задано значение 1–40. ECC по умолчанию — M. Ошибки имеют стабильный тип
`QrEncodingError` и код: например, `EMPTY_PAYLOAD`, `INVALID_VERSION` или
`CAPACITY_EXCEEDED`.

`renderQrSvg` синхронно возвращает самодостаточный SVG без обращения к DOM,
серверу или encoder. Одну матрицу можно рендерить повторно с другим оформлением.
Поддерживаются квадратные, скруглённые и круглые data-модули, отдельная форма
finder patterns, сплошной цвет или общий двухцветный линейный градиент,
растровый логотип, квадратное или круглое оформление, надписи и простая рамка. Timing, alignment и остальные
служебные модули остаются квадратными. Логотип принимается как base64 PNG, JPEG
или WebP; SVG data URI исключены, а область логотипа не может закрывать служебные
модули. Quiet zone по умолчанию равна 4 модулям и не может быть меньше.

`finder` оформляет каждый угловой маркер целиком: `outerShape` выбирает кольцо,
`innerShape` — центральную фигуру, `outerColor` и `innerColor` — независимые цвета.
Формы: `square`, `rounded`, `circle`; без цвета используется заливка матрицы.
Старый `finderShape` сохраняет оформление отдельных клеток для совместимости;
при наличии `finder` приоритет у цельных маркеров.
Градиент использует единые координаты всей QR-матрицы (`userSpaceOnUse`), включая
маркеры без своих цветов; переход не повторяется внутри каждой клетки.

`frame` принимает `"none"`, прежний `"outline"` или объект
`{ style: "outline", color: "#173d51", widthPx: 3 }`. У объекта толщина задаётся
в пикселях экспорта (по умолчанию 2); геометрия резервирует под неё место за quiet zone.
`artworkBackground` задаёт внешний фон отдельно от `background`: вся квадратная
подложка QR вместе с quiet zone сохраняет `background`, даже если внешняя область тёмная.

Для круглого оформления используйте `shape: "circle"`. Круг вмещает всю квадратную
матрицу вместе с quiet zone; углы SVG и PNG за пределами круга прозрачны.
`size` задаёт ширину всей композиции: при той же ширине круг уменьшает размер
модуля по сравнению с квадратом, что учитывается в `analyzeQrDesign`.
Добавление дуговых надписей не меняет масштаб QR.

`caption` принимает одну надпись (по умолчанию снизу) или массив из двух, сверху
и снизу. `position` — `top` / `bottom`, `style` — `plain`, `banner` или `arc`
(дуга доступна для круга). `fontSize` задаёт размер текста в пикселях экспорта,
по умолчанию 18; текст автоматически уменьшается, чтобы поместиться без измерений DOM.
Дуговые надписи вписываются в свободные области над и под quiet zone; SVG `textLength`
фиксирует длину строки вдоль дуги, чтобы широкие символы не выходили за рассчитанную область.
`color` и `background` задают цвет текста и полосы. Прямые надписи увеличивают высоту
изображения. Можно сочетать прямую надпись и дугу.
У каждой строки независимы `fontWeight` (400, 500, 600, 700), `letterSpacing`
(0–10 пикселей экспорта), размер и цвета. При уменьшении текста интервал уменьшается
пропорционально; дуговой текст по-прежнему не уменьшает сам QR.

```ts
const brandedSvg = renderQrSvg(matrix, {
  size: 512,
  shape: "circle",
  finder: { outerShape: "rounded", innerShape: "circle" },
  frame: { color: "#173d51", widthPx: 3 },
  caption: [
    {
      text: "QR STUDIO",
      position: "top",
      style: "arc",
      fontSize: 32,
      fontWeight: 600,
      letterSpacing: 1,
    },
    { text: "Открыть меню", position: "bottom", style: "arc", fontSize: 24 },
  ],
});
```

`analyzeQrDesign` возвращает измеренный коэффициент контраста для сплошных цветов,
ширину модуля в пикселях и предупреждения о рискованных настройках. Порог контраста
и минимальный размер модуля задаются вызывающим кодом после отдельных проверок;
движок не выдаёт неподтверждённые значения за гарантию считывания. Для градиентов и
логотипа диагностика прямо рекомендует проверку на целевых устройствах.

Движок не импортирует Vue. Корневого entrypoint пока нет: потребители используют
`/engine`; `/editor` и `/ui` появятся вместе с соответствующей реализацией.
Сборка — ESM и декларации `.d.ts`; `qr` остаётся runtime-зависимостью.

## Ошибки и локализация

Engine возвращает ошибки `QrError` с `code` и типизированными `params`, без
пользовательского текста. `QrEncodingError` наследует этот контракт.
Предупреждения `analyzeQrDesign` также содержат `code`, `severity` и `params`.
Язык выбирает приложение через отдельные entrypoint:

```ts
import { encodeQr, QrError } from "@qr-studio/toolkit/engine";
import { formatQrError, formatQrDiagnostic } from "@qr-studio/toolkit/i18n";
import { qrMessagesRu } from "@qr-studio/toolkit/i18n/ru";

try {
  encodeQr("https://example.com", { version: 0 });
} catch (error) {
  const text = formatQrError(error, qrMessagesRu);
  // «Версия QR должна быть целым числом от 1 до 40.»
  if (error instanceof QrError) {
    console.log(error.code, error.params); // INVALID_VERSION, { minimum: 1, maximum: 40 }
  }
}

const texts = diagnostics.map((item) => formatQrDiagnostic(item, qrMessagesRu));
```

В комплекте есть русский `qrMessagesRu` и английский `qrMessagesEn`. Словари
импортируются отдельно; для английского передайте мапперу `qrMessagesEn`:

```ts
import { qrMessagesEn } from "@qr-studio/toolkit/i18n/en";

const englishTexts = diagnostics.map((item) => formatQrDiagnostic(item, qrMessagesEn));
```

Для другого языка приложение передаёт собственный `QrMessageCatalog`: `errors`
и `diagnostics` сопоставляют каждому коду функцию от параметров, `unknownError`
задаёт общее сообщение. TypeScript проверяет полноту словаря и параметры каждой
функции. Каталог можно хранить в приложении или адаптировать к его i18n-системе;
engine не импортирует словари и не хранит текущий язык. Числа в `params` остаются
числами: округление и форматирование выполняет словарь.

`formatQrError` для неизвестного исключения возвращает `unknownError` или
переданный третьим аргументом текст. Технические `message`, `cause` и
`originalError` не выводятся пользователю; исходная причина ошибки encoder
сохраняется для отладки. `Error.message` у `QrError` содержит код.

Изменение контракта: валидация renderer и диагностики теперь бросает `QrError`
вместо `TypeError` / `RangeError`, у диагностик больше нет `message`.
Обработчики должны использовать `code` / `params` и маппер. Конструктор
`QrEncodingError` также принимает параметры вместо готового текста;
прежние коды encoder сохранены. Playground использует русский словарь.

## Внешние пресеты

Engine не содержит каталога пресетов и не принимает ID пресета. Он принимает обычный
`RenderQrSvgOptions`, поэтому оформление может приходить из конфигурации, API или Brand Kit:

```ts
// Метаданные и загрузка принадлежат вызывающему приложению.
const selectedPreset = {
  id: "brand-ocean",
  design: {
    foreground: "#173d51",
    finder: { outerShape: "rounded", innerShape: "circle" },
  },
} satisfies { id: string; design: import("@qr-studio/toolkit/engine").RenderQrSvgOptions };
const presetSvg = renderQrSvg(matrix, selectedPreset.design);
```

Демонстрационные данные находятся только в `playground/presets.ts`: минимализм,
ATELIER, технологичный, яркий, строгий и брендовый знак. `setPlaygroundPresets(catalog)`
из `playground/main.ts` заменяет каталог любым переданным массивом `PlaygroundPreset`.
`applyPlaygroundDesign(design)` применяет произвольный объект оформления без каталога.
Эти функции относятся только к тестовой странице; будущий Vue-компонент сможет принимать
собственный каталог и передавать выбранное оформление напрямую в engine.
Пресеты playground меняют только визуальные параметры: содержимое, ECC, версия,
размер экспорта, quiet zone и загруженный логотип сохраняются.

## Команды из корня репозитория

```sh
pnpm install
pnpm --filter @qr-studio/toolkit build
pnpm --filter @qr-studio/toolkit check
pnpm --filter @qr-studio/toolkit test
pnpm --filter @qr-studio/toolkit playground
```

`playground` запускает локальную страницу на обычных HTML/CSS/TypeScript и Vite.
Пресеты проверяют URL, Unicode и переносы строк, длинное содержимое и переполнение
версии 1; вручную доступны ECC и версия, размер, quiet zone, формы модулей и finder-маркеров,
цвета, градиент, общая форма, рамка, логотип и надписи сверху/снизу, в том числе
по дуге круга. У надписей независимо настраиваются стиль, размер, насыщенность,
межбуквенный интервал и цвета; у обрамления — цвет, толщина и внешний фон.
SVG-предпросмотр и SVG-файл используют одну
строку Renderer; PNG браузер растеризует из этого SVG. Диагностика показывает шаг модуля,
контраст и площадь логотипа, но не гарантирует сканирование. Кнопка проверки использует
`BarcodeDetector`, если он поддерживается браузером; иначе откройте экспорт на другом экране
и проверьте камерой телефона. Содержимое и выбранный логотип обрабатываются локально.
При пустом вводе или ошибке экспорт недоступен.
`dev` пересобирает библиотеку при изменениях.
`build:playground` собирает страницу в `dist-playground`, отдельно от библиотеки.

Версия Node закреплена в корневом `.nvmrc`: перед работой выполните `nvm use`.
Версия pnpm должна совпадать с корневым `packageManager` (`12.11.2`).

## VS Code

Откройте в VS Code обычную корневую папку `QR Studio`. Настройки `.vscode/settings.json`
направляют расширение Oxc к локальным `oxlint` и `oxfmt` из toolkit. После первой
установки зависимостей, если редактор не обнаружил бинарники, выполните команды
**Oxc: Restart oxlint Server** и **Oxc: Restart oxfmt Server**.

`build` компилирует библиотеку через `tsc`, `test` запускает Vitest, `lint` — Oxlint,
`format` — Oxfmt. Команда `check` объединяет lint, проверку типов и форматирования.

## Проверки и границы версии

Тесты проверяют контракт матрицы и служебных областей для всех 40 версий,
Unicode-round-trip через decoder, поставляемый тем же пакетом `qr`, SVG-геометрию,
варианты стилей, диагностику и входные ограничения. Это проверка отдельного пути
декодирования, но не независимого стороннего сканера; рендеринг SVG в браузере и
считывание физическим телефоном проверяются отдельно.
В ручной проверке шесть демо-пресетов экспортированы браузером в PNG и декодированы
через `qr/decode.js` с совпадением исходной ссылки (версия 3, ECC Q, ширина 512 px).
Этот результат относится к проверенным изображениям и не заменяет проверку телефоном.

Это базовый технический срез, а не завершённый Scan-safe или редактор:

- В engine нет PNG exporter; PNG формируется в браузере playground. Vue UI и сохранение проектов ещё не реализованы.
- Контраст измеряется, но универсальный порог и безопасный размер логотипа не утверждены.
- Считывание градиентов, форм, логотипов и печатных образцов требует отдельной проверки.
- Производительность стилизованного SVG на телефонах ещё не измерена; обычный квадратный
  вывод сохраняет компактное объединение соседних модулей в path.
- Encoder `qr` использует один сегмент; смешанные payload могут давать более
  плотную матрицу, чем при оптимизированной сегментации.
